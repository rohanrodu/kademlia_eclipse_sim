How It Works

Four concepts, in order: node distance, the attack, the defense, and how to read the simulation.

1

Every node has an ID, and a "distance"

Each peer gets a random {{ params.id_bits }}-bit ID. Distance between two nodes isn't physical — it's the XOR of their IDs. Peers get grouped into buckets by how close they are: bucket = floor(log2(id_a XOR id_b)). Small XOR → low bucket number → "close". Large XOR → high bucket → "far".

A healthy routing table keeps connections spread across many buckets, not just the closest one.

2

The eclipse attack

The attacker mints many node IDs close to the victim's ID (cheap — IDs are just numbers) and floods the network with them. If peer selection is naive random sampling, the victim's connection slots end up reflecting whatever share of the visible network is attacker-controlled.

Once a majority of a victim's active connections are attacker peers, the attacker fully controls what the victim sees: it can hide transactions, feed stale or false data, or isolate the victim from the honest network entirely.

3

The defense: TABSD

Trust-weighted Adaptive Bucket & Subnet Diversity combines three independent layers so an attacker has to beat all three at once:

  • Bucket diversity — at least one connection is guaranteed per occupied XOR bucket, so attacker IDs clustered near the victim can only ever dominate the low buckets, never the whole table.
  • Subnet capping — no more than {{ params.max_per_subnet }} connections may come from the same simulated subnet, regardless of ID. This targets the real-world limit on how many actual machines an attacker controls.
  • Trust-weighted gating — brand-new peers are capped to about {{ (params.new_peer_cap_ratio * 100) | round(0) }}% of connection slots per round, and selection favors peers with a longer track record. A flood of new peers can't win in a single round.
4

Reading the live simulation

On the Simulation page, every dot is a peer positioned by its distance from the victim (center) — closer dots are in lower buckets. Blue = honest, red = malicious.

Step through rounds to see which peers get connected under each strategy. A round is marked ECLIPSED when more than half of the victim's connections are malicious.

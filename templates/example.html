Worked Example

One real, reproducible run of the algorithm — the exact input, the intermediate math, and the exact output. Not illustrative numbers: this is what the code actually produces.

Input

What goes in

A victim node ID and a small network are generated from a fixed random seed, so the result below is 100% reproducible.

{
  "victim_id": 164,
  "num_honest": 12,
  "num_attackers": 8,
  "attacker_subnet_span": 2,
  "seed": 7
}

victim_id = 164 → binary 10100100. The attacker mints 8 fake IDs close to this value (classic eclipse strategy); the 12 honest peers get random IDs anywhere in the 8-bit space.

Step 1

Every peer gets a distance & bucket

bucket = floor(log2(victim_id XOR peer_id)) — smaller bucket number means closer to the victim. Notice how every single malicious peer lands in buckets 1–3, while honest peers are scattered from bucket 1 all the way to bucket 7.

Step 2

Same network, two different outcomes

Random Selection

3 / 8

malicious connections

Uniform sampling has no idea some of these IDs are suspiciously close to the victim — it picked 3 of the 5 malicious peers in bucket 1–3, plus 5 honest peers scattered wherever the sample happened to land.

TABSD Defense

1 / 8

malicious connection

Bucket diversity forced at least one pick from far buckets (6, 7) where no attacker exists. Subnet capping blocked extra picks from subnet 12, which 5 of the 8 malicious peers shared. Only 1 malicious peer got through.

Neither run was "eclipsed" here (that needs >50%), but notice the gap: TABSD cut the attacker's success rate from 37.5% to 12.5% on the exact same network.

Field guide

  • network — every peer known this round: key (unique internal id, since real node IDs can collide by design), id (the Kademlia node ID), subnet, malicious, trust (rounds of good behavior accumulated), and bucket (distance from the victim).
  • vulnerable / secure — each strategy's result: which peer keys got connected, how many were malicious, and whether that round counts as eclipsed (malicious > half of total connections).
